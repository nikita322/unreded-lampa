# Agents.md — Lampa (SolidTV) · архитектура и план миграции

> Единый источник правды для рефакторинга Lampa на SolidTV.
> Рабочий цикл: **один этап за раз → ветка → коммит → отчёт → стоп до подтверждения**.

---

## 1. О проекте

Lampa — self-hosted медиаплеер для стриминга (TV-first, управление пультом).
Текущий код: vanilla JS + jQuery-подобный слой, сборка Gulp, императивные DOM-манипуляции.

**Цель рефакторинга:**
1. Убрать jQuery и ручные DOM-операции → fine-grained реактивность.
2. Снизить количество DOM-операций на кадр и bundle size.
3. Пульт (LRUD: left/right/up/down/enter/back) — основной способ ввода.

**Границы:**
- Плеер остаётся нативный `<video>` — не переписываем.
- Набор экранов для переноса определяется этапами; при неясности — спрашивать.

---

## 2. Целевой стек

- `@solidtv/solid@^1.7` + `@solidtv/renderer@^2.0` + `solid-js@^1.9`
- `@solidjs/router@^0.16.3` — строго эта линия (peer у SolidTV; `1.x` несовместим)
- TypeScript `strict`
- Vite + `vite-plugin-solid` (`moduleName: '@solidtv/solid'`, `generate: 'universal'`)
- Токены дизайна — централизованные TS-константы (без CSS-in-JS рантаймов)
- Тесты — Vitest (вводится с этапа 4)
- **Запрещено:** jQuery, lodash, moment и любые тяжёлые зависимости

---

## 3. Принципы (нерушимые)

1. **Строгая типизация.** `strict: true`, `noImplicitAny: true`. Ни одного `any` в публичных API.
   Для неизвестного типа — `unknown` + type guard. Ни одного `@ts-ignore` / `@ts-expect-error`.
2. **DRY.** Одна ответственность — одно место. Без копипаст-блоков, общие вещи — в `utils/`/`theme/`/`constants/`.
3. **KISS.** Проще — значит лучше. Абстракцию вводим только когда она реально нужна, не «на вырост».
4. **Никаких магических строк/чисел** в логике и JSX. Цвета, отступы, шрифты, тайминги,
   коды/имена клавиш, имена роутов/событий/ключей хранилища — только именованные константы.
5. **Централизованные дизайн-токены** — единая палитра, шкала отступов, типографика, motion (см. §6).
6. Один корневой `<App />` + сигнал `activityStack`.
7. Фокус — через сигнал `focusedIndex`; **один** `keydown`-обработчик на `document` (`useFocusManager`).
8. Все списки рендерятся декларативно; узлы переиспользуются реактивностью SolidJS — не пересоздавать дерево при навигации.
9. Сетевые данные кэшируются с версионированием (`cache`/`db`).
10. Изображения — lazy + async decode; в canvas — lazy-префетч вне вьюпорта.
11. Никаких чтений `offsetWidth`/`getBoundingClientRect` во время записи в DOM.
12. Анимации — `transform`/`opacity` (в canvas — `animationSettings`), без layout-свойств.
13. Плеер — нативный `<video>` через ref.
14. Никаких глобальных `Lampa.*` — состояние через сигналы/контекст.
15. Ввод делегирован на корень приложения.
16. **Тесты.** Весь функционал покрыт тестами. Тесты вдумчивые: проверяют поведение
    и контракты, а не банальные вещи (см. §7 «Тестирование»).

## 4. Архитектура рантайма

```
bootstrap (src/index.tsx)
  createRenderer(размер окна)  →  loadFonts(когда появится текст)  →  useFocusManager(keymap)
  →  render(<App />)
```

- **App** владеет сигналом `activityStack`. `Activity.push/pop` меняют сигнал, а не DOM.
- **Фокус** — `focusedIndex`; обработка ввода — делегирована, не вешается на карточки.
- **Данные:** `api` → `cache/db` (версионирование) → компоненты экрана.
- **Плеер:** нативный `<video>` через ref; события плеера пробрасываются сигналами.
- **Пульт:** LRUD + Enter + Back (`Last`/Escape); в dev — эмуляция клавиатурой через `keymap`.
- **Моки:** `src/mocks/` (заглушки потоков/API), включаются флагом `VITE_ENABLE_MOCKS`.

**Локальный запуск (обязательно на каждом этапе):**
- `npm run dev` — одной командой, Vite dev-server, HMR, порт **5173**.
- Без обязательных переменных окружения; `.env.example` — только дефолты.
- Без docker/внешних БД; приложение работает «из коробки».

## 5. Структура папок

```
src/
  index.tsx          # bootstrap
  App.tsx            # корневой компонент + activityStack
  keymap.ts          # маппинг пульта на клавиатуру
  vite-env.d.ts
  config/            # рантайм-конфигурация (screen и т.п.)
    screen.ts
  constants/         # именованные строки/числа (без магии в коде)
    keys.ts          # клавиши/коды
    routes.ts        # роуты (этап 2+)
    storage.ts       # ключи хранилища (этап 4+)
    api.ts           # endpoints (этап 4+)
  theme/             # дизайн-токены
    palette.ts
    spacing.ts
    typography.ts
    motion.ts
    layout.ts
    index.ts         # barrel
  components/        # переиспользуемые SolidTV-компоненты (этап 5+)
  player/            # обёртка <video> (этап 3)
  api/               # порт api.js (этап 4)
  cache/             # порт cache/db (этап 4)
  utils/             # общие утилиты
  mocks/             # заглушки потоков/API (этап 3+)
legacy/              # старый код — эталон для порта (не редактировать, не билдить)
  src/
  public/
```

Правила:
- `legacy/` — только чтение как источник логики; в сборку/типизацию не попадает.
- Новый код — только в `src/`.
- Переиспользуемое — в `components/`/`utils/`; экранные вещи — рядом с экраном.

## 6. Дизайн-токены (централизованные)

Все визуальные значения живут в `src/theme/` и импортируются оттуда. **Сырые числа в JSX запрещены.**

- `palette.ts` — цвета SolidTV в формате `0xRRGGBBAA`.
- `spacing.ts` — шкала отступов (логические px, шаг 4).
- `typography.ts` — шрифты/размеры/веса (с этапа, где появится текст).
- `motion.ts` — длительности/easing анимаций.
- `layout.ts` — базовые размеры/соотношения контента.
- `index.ts` — barrel-реэкспорт.

Правила токенов:
1. Всегда `as const` — литеральные типы, а не `number`/`string`.
2. Имена семантические (`background.base`, `accent.primary`), не «blue1».
3. Потребитель обращается только через `import { palette } from '../theme'`.
4. Новый цвет/отступ сначала добавляется в токены, потом используется.

Пример:

```ts
// src/theme/palette.ts
export const palette = {
  background: { base: 0x0b1026ff },
  accent: { primary: 0x2f81f7ff },
} as const;

// src/theme/spacing.ts
export const spacing = {
  xxs: 4, xs: 8, sm: 12, md: 16, lg: 24, xl: 32, xxl: 48, xxxl: 64,
} as const;
```

## 7. Стандарты кода и типизации

- Публичный API (компоненты, утилиты, провайдеры) — всегда типизирован, без `any`.
- Интерфейсы — для публичных контрактов; `type` — для объединений/алиасов/производных.
- Константы проверяем `satisfies` (например, `satisfies Partial<KeyMap>`).
- Имена констант — `SCREAMING_SNAKE_CASE`; токены/конфиги — объекты `as const`.
- Один компонент = один файл; экспорт экрана — default, переиспользуемое — named.
- Файлы держать небольшими; комментарии — только «почему», не «что».
- Ошибки сети/парсинга обрабатываются явно; типы ответов API описаны интерфейсами.
- Никакого состояния вне сигналов/контекста; никаких глобальных переменных.

### Тестирование

- **Покрываем тестами весь функционал** — но вдумчиво, по контрактам и поведению.
- **Тестируем:** бизнес-логику (activity-стек, фокус/навигация, кэш с TTL/инвалидацией,
  парсинг ответов API), публичные API, граничные случаи, регрессии исправленных багов.
- **Не тестируем банальности:** тривиальные геттеры/сеттеры без логики, пасовку пропсов,
  константы/токены, сам рендерер SolidTV, мок-данные.
- Имя теста формулирует поведение: «что делает → что ожидаем»
  (например, `pop не снимает последний экран`).
- Тесты детерминированы и изолированы: без реальной сети (моки/фейки), без зависимости
  от порядка выполнения и таймеров.
- Раннер — Vitest, вводится с этапа 4 (первая чистая логика для тестов — кэш);
  `npm test` — обязательная проверка.

## 8. План миграции (этапы)

Каждый этап: ветка `stage-N-<slug>` от `main`, коммиты `stage-N: <описание>`, в конце — отчёт и стоп.

### Этап 1 — Настройка (✅ выполнено, `7e149389`)
Vite + TS strict + SolidTV, адаптивный экран-заглушка, рабочий `npm run dev` + HMR.
Готово когда: `npm run dev` на 5173, `npm run build` без ошибок, старый код в `legacy/`.

### Этап 2 — activity → сигнал + `<App />` (✅ выполнено, `5628d9cb`)
Порт `legacy/src/interaction/activity.js`: сигнал `activityStack`, `Activity.push/pop` без DOM.
Две экранные заглушки; навигация `Enter` (вперёд) и `Back`/Escape (назад), стрелки — движение фокуса.
Готово когда: переходы работают с клавиатуры; дерево не пересоздаётся; нет глобального `Lampa.Activity`.

### Этап 3 — player (✅ выполнено, `e67db16b`)
Обернуть нативный `<video>` в SolidTV-компонент через ref; тестовый поток из `src/mocks/`.
Готово когда: воспроизведение мок-потока, управление play/pause, очистка при pop.

### Этап 4 — api + cache/db
Порт `api.js` и кэша без UI; юнит-тесты кэша (версионирование, TTL/инвалидация).
Готово когда: тесты зелёные, публичные API типизированы, ключи/endpoints — в `constants/`.

### Этап 5 — первый экран на компонентах
Один реальный экран на SolidTV-компонентах; навигация пультом; замер DOM-операций в DevTools.
Готово когда: нет Layout/Recalculate Style на кадр; карточки фокусируются по `focusedIndex`.

### Этап 6 — остальные экраны
Последовательный порт остальных экранов; удаление мёртвых зависимостей из `legacy/`.
Готово когда: все целевые экраны работают, мёртвый код удалён.

### Этап 7 — финальная чистка
Профилирование, замер bundle, удаление Gulp/старых конфигов, финальная типизация.
Готово когда: bundle основного чанка < 150 КБ gzip, нет jQuery/lodash/moment, `any`=0.

## 9. Definition of Done этапа

1. `npm run dev` работает одной командой (порт 5173, HMR) и показывает результат этапа.
2. `npm run build` (включая `tsc --noEmit`) — без ошибок.
3. В новых файлах: 0 `any`, 0 `@ts-ignore`, 0 магических строк/чисел.
4. Токены/константы используются через `theme/` и `constants/`, не сырыми значениями.
5. Новый функционал покрыт вдумчивыми тестами (с этапа 4); `npm test` зелёный.
6. Отчёт по шаблону (§10) + стоп до явного подтверждения следующего этапа.

## 11. Журнал решений и открытые вопросы

**Принято:**
- SolidTV (`@solidtv/solid`) — доступен и проверен, fallback не нужен.
- `@solidjs/router@^0.16.3` — из-за peer-зависимости SolidTV.
- Этап 1 без текста: canvas-текст требует SDF-атласа; шрифт добавим на этапе 2/5.
- Размер интерфейса — из реального layout-размера `#app` (`clientWidth/clientHeight` + DPR),
  а не из `window.innerWidth/Height`; страница без скроллов (`overflow: hidden`).
- Старый код перенесён в `legacy/` через `git mv` (история сохранена).
- `package-lock.json` остаётся в `.gitignore` (как было в репозитории).

**Открыто:**
- COEP `require-corp` в `vite.config.ts` — до этапа 5 может мешать загрузке постеров с CDN без CORP; кандидаты: `credentialless` или убрать.
- Живой resize окна — отложен; при необходимости добавить пересоздание рендерера.
- Явный фолбэк `DEFAULT_SCREEN` убран; рендерер сам подставляет 1920×1080, если размер оказался 0 (крайний случай ТВ-хостов).
